# PAT-001 幂等键模式

## 何时用

所有跨 BU 写接口（HTTP POST/PUT、命令类事件）。判定口诀：**调用方敢重发的写，就必须有幂等键**。

## 怎么做

1. 调用方生成并持久化幂等键（重试复用同一键）；
2. 传输：`Idempotency-Key` 请求头（≤64 字符，见 ORD-CREATE.v1）；
3. 提供方：首次请求将 {键 → 响应摘要} 落存 **≥24h**；重复同体请求返回首次响应（含状态码）；
4. 同键**不同**请求体 → `409`，绝不"后者覆盖前者"；
5. 事件侧变体：消费方按业务主键（如 `orderId`）去重，见 S-003 断言 3。

## 反模式

- 用时间戳/随机数当去重键（每次重试都不同 → 失效）；
- 幂等窗口 = 进程内存（重启即失忆）；
- 先执行业务副作用再判重（409 时库存已扣）。

## 怎么验证

契约场景 S-002 断言 2/3 是标准测试；test-weaver Agent 可从场景直接生成骨架。
